# Live Transcriber — инструкция для работы над проектом

Приложение в строке меню macOS на Swift: диктовка по Fn с вставкой туда, где курсор,
и запись созвонов с расшифровкой, итогом и отправкой в Telegram. Работает целиком
на маке. Что умеет и как пользоваться — в README.md, здесь только работа с кодом.

- Папка: `/Users/sashafyc/Documents/live transcriber`
- Репозиторий: github.com/sashafyc/live-transcriber (публичный)
- Ветка одна: `main`
- Сборка: SwiftPM без проекта Xcode, но нужен полный Xcode (`DEVELOPER_DIR` задаёт `build.sh`)
- До 2.0 была Python-версия (rumps + ffmpeg), она в истории git до тега v1.4.0

## Порядок правки

1. Править код, собирать и ставить: `./build.sh --install` (сам перезапускает приложение)
2. Коммит обычным сообщением: что починили и почему, без номера версии
3. Релиз одной командой — она поднимет номер в Info.plist, допишет историю изменений,
   обновит значок версии в README, сделает коммит, тег и релиз на GitHub с архивом:

```bash
cd "/Users/sashafyc/Documents/live transcriber" && scripts/release.sh patch "Что починили одной фразой"
```

Вместо `patch` бывает `minor` (новая возможность) и `major` (ломающее изменение);
третий аргумент — раздел: `fixed` (по умолчанию), `added`, `changed`.
Скрипт требует чистое дерево, поэтому шаг 2 обязателен. Нужен `gh` с авторизацией.

## Проверки без окон

Запускать только через `open -n`, иначе разрешение на звук системы macOS спросит
у терминала, и дорожка собеседника будет пустой. Результат пишется в файл:

```bash
open -n -a "/Applications/Live Transcriber.app" --args --sound-check /tmp/sound.txt
```

| Флаг | Что делает |
|---|---|
| `--sound-check <файл>` | то же, что «Проверить звук» |
| `--record-test <секунды> <папка>` | пишет созвон заданной длины в `audio.flac`, уровни кусков в `report.txt` |
| `--transcribe <audio.flac> <файл>` | расшифровка записи целиком, как «Расшифровать заново» |
| `--summarize <transcript.md> <файл>` | итог через DeepSeek |
| `--check-keys <файл>` | ключи DeepSeek и Telegram; в чат ничего не пишет |
| `--check <провайдер> [модель]` | распознавание диктовки синтезированной фразой (вывод в терминал) |
| `--format <провайдер> [модель]` | оформление диктовки (вывод в терминал) |

## Грабли, проверенные на этом маке

- **Ответвление системного звука (process tap).** Звук собеседника пишется копией
  того, что слышит пользователь, выход не переключается. Без любого из условий —
  тишина без единой ошибки: идентификатор ответвления в верхнем регистре (иначе
  устройство создаётся без входных потоков), `NSAudioCaptureUsageDescription` в
  Info.plist и разрешение «Запись экрана и звука системы».
- **Ответвление отдаёт звук, только пока что-то играет.** В тишине поток стоит,
  а не шлёт нули. Выравнивание дорожек «по старту» поэтому срезало начало созвона,
  пока собеседник молчал. Каждый кусок кладётся на общую шкалу времени по
  `mHostTime`, пропуски заполняются тишиной (`CallCapture.Track`). Проверено:
  дорожки сходятся до 60 мс — это задержка звука от динамиков до микрофона.
- **Разрешения выдаются приложению, а не процессу.** Тот же код из терминала даёт
  тишину. Проверять только на собранном приложении, запуская через `open -n`.
- **Подпись.** Apple Development (бесплатный Apple ID в Xcode) не меняется между
  сборками, и разрешения не слетают. Не работала, пока в связку не добавили
  промежуточный сертификат AppleWWDRCAG3 (был только истёкший WWDR 2023). С ad-hoc
  подписью разрешения слетают при каждой пересборке. Идентификатор приложения
  `pro.ainvest.livetranscriber`; у версий 1.x был другой, поэтому при обновлении
  с 1.x разрешения выдаются заново.
- **Бандл собирается вне Документов.** Папку синкает iCloud, File Provider вешает на
  `.app` атрибуты сразу после `xattr -cr`, и `codesign` падает с «detritus not
  allowed». `build.sh` при этом молча не ставил новую сборку: сборка в `$TMPDIR`.
- **Свои устройства нельзя предлагать как микрофон.** Ответвление выглядит как
  обычный вход, и выбор «лучшего микрофона» однажды записал приложение само в себя.
  Микрофон отбирается по типу подключения: виртуальные (BlackHole, Zoom), составные
  и микрофон айфона отсеиваются. Ищется заново прямо перед стартом и по UID,
  не по номеру: 22.09.2026 номер входа сдвинулся, пока было открыто окно, и вместо
  микрофона писалась пустая виртуальная карта.
- **Ровный ноль на дорожке — поломка, а не тишина.** Живой микрофон всегда даёт хотя
  бы шум. Захват проверяет первые пять секунд по сырому звуку до округления в 16 бит
  и один раз сам перезапускает микрофон. Тревога «микрофон молчит» — ниже 3, а не
  общего порога тишины 15: без обработки ffmpeg тихая комната даёт фон около 6.
- **Дорожки, а не смесь.** Микрофон — левый канал, собеседник — правый. Расшифровка
  получает `multichannel` и не гадает, кто говорит: в смеси метки спикеров у каждого
  куска свои, и один человек превращался в нескольких.
- **Колонки вместо наушников ломают разделение по дорожкам.** Микрофон слышит
  собеседника, и одна речь распознаётся дважды разными словами — отсев по тексту
  бессилен. `duckBleed` глушит кадры микрофона, которые лишь повторяют собеседника
  тише него: замер 22.09 — просачивание 0.28 от громкости собеседника, своя речь
  громче втрое и остаётся.
- **Собеседник может звучать в микрофон** (громкая связь, встреча за одним столом),
  поэтому голоса на дорожке микрофона тоже разделяются, и самый говорящий считается
  хозяином микрофона.
- **Титры переводчиков в расшифровке — выдумка распознавания.** Тихая неразборчивая
  речь даёт «Редактор субтитров А.Семкин Корректор А.Егорова» с уверенностью 0.76 —
  по уверенности не отсечь, только по тексту. Чем меньше тишины уходит, тем меньше
  выдумок: паузы длиннее 3 секунд вырезаются, пустая дорожка не отправляется.
- **Внешний созвон пишется одной дорожкой.** Разговор по телефону идёт мимо
  компьютера, вторая дорожка была бы пустой, а на ней распознавание сочиняет титры.
  Хозяин дорожки известен заранее (`solo = "Я"`), и моно-запись при переделке
  тоже считается дорожкой микрофона.
- **AssemblyAI пакетно принимает только universal-2 / universal-3-5-pro /
  universal-3-pro** (3.6 — только поток). Русский надёжно знает universal-2. Между
  прогонами одной записи сервис иногда находит разное число голосов — это не код.
- **Звук записи сохраняется** в `audio.flac` и живёт неделю: без него жалобы на
  расшифровку разбирать нечем. Оттуда же работает «Расшифровать заново».
- **Окна созвонов немодальные и на AppKit** (`Windows`): их открывает не меню, а
  сама обработка, а пока открыто модальное окно, меню в строке состояния не отвечает.
- **Регулярки.** В режиме Swift 5 литералы только `#/…/#`, просмотра назад в них
  нет — для курсива в Telegram стоит `NSRegularExpression`.
- **`strings` не видит кириллицу** — свежесть сборки им не проверить.
- **Звуковой сервис иногда виснет целиком**: устройства не отдают звук. Лечится
  `sudo killall coreaudiod`, пароль вводит Саша.
- **OpenAI из России работает только с VPN.** Подписка ChatGPT в код не попадает:
  она подключается отдельным локальным переходником через «Свой адрес».

## Секреты

Ключи — в связке ключей (сервис `pro.ainvest.livetranscriber`), остальные настройки —
в UserDefaults. `config.json` в `~/Library/Application Support/Live Transcriber/`
остался от 1.x и читается один раз для переноса ключей. Перед коммитом проверять,
что в коде нет ни ключей, ни настоящего идентификатора чата — реальный id однажды
утёк в пример в докстринге. Адрес Telegram содержит токен бота, в лог его не писать.

## Проверка перед релизом

- `--sound-check`: микрофон слышит, звук собеседника доходит
- `--record-test` с речью в динамики: обе дорожки, расшифровка без дублей
- Короткая запись через меню целиком: расшифровка, итог, окно итога, сообщение в Telegram
- Диктовка по Fn вставляет текст
- Меню после остановки: значок обычный, пункты активны; история открывается
