# Live Transcriber — инструкция для работы над проектом

Приложение в строке меню macOS: пишет созвон, расшифровывает, делает итог,
шлёт в Telegram. Работает целиком на маке, сервер и агент Scriber из цепочки
убраны. Что умеет и как пользоваться — в README.md, здесь только работа с кодом.

- Папка: `/Users/sashafyc/Documents/live transcriber`
- Репозиторий: github.com/sashafyc/live-transcriber (публичный)
- Ветка одна: `main`
- Питон проекта: `.venv/bin/python3` (3.13). Системный 3.9 код не прочитает.

## Карта кода

| Файл | За что отвечает |
|---|---|
| `main.py` | точка входа, три строки |
| `livetranscriber/__init__.py` | номер версии, его правит только `scripts/release.py` |
| `livetranscriber/app.py` | меню в строке состояния, порядок шагов, значок состояния |
| `livetranscriber/audio.py` | устройства, aggregate LT-Auto, запись чанками, диагностика звука |
| `livetranscriber/transcribe.py` | сжатие в mp3, загрузка и расшифровка в AssemblyAI, ретраи |
| `livetranscriber/summarize.py` | итог через DeepSeek, длинные расшифровки по частям |
| `livetranscriber/telegram.py` | отправка итога в чат или тему группы |
| `livetranscriber/windows.py` | все окна, разметка в окнах, буфер обмена |
| `livetranscriber/markup.py` | общий разбор разметки для окон и Telegram |
| `livetranscriber/storage.py` | папки записей, логи, удаление старше 30 дней |
| `livetranscriber/config.py` | ключи и настройки, разбор ссылки на чат |
| `scripts/build_app.py` | сборка `.app` через py2app |
| `scripts/release.py` | версия, история изменений, тег, релиз на GitHub |
| `scripts/make_icon.py` | иконка приложения |

## Порядок правки

1. Править код, запускать из исходников: `.venv/bin/python3 main.py`
2. Коммит обычным сообщением: что починили и почему, без номера версии
3. Релиз одной командой — она поднимет номер, допишет историю изменений,
   обновит значок версии в README, сделает коммит, тег и релиз на GitHub:

```bash
cd "/Users/sashafyc/Documents/live transcriber" && .venv/bin/python3 scripts/release.py patch "Что починили одной фразой"
```

Вместо `patch` бывает `minor` (новая возможность) и `major` (ломающее изменение).
Скрипт требует чистое дерево, поэтому шаг 2 обязателен. Нужен `gh` с авторизацией.

4. Пересобрать и переустановить, иначе у пользователя останется старая версия:

```bash
cd "/Users/sashafyc/Documents/live transcriber" && .venv/bin/python3 scripts/build_app.py && pkill -x "Live Transcriber"; rm -rf "/Applications/Live Transcriber.app" && cp -R "dist/Live Transcriber.app" /Applications/
```

Запускать приложение после установки не нужно: Саша запустит сам. Каждый запуск
открывает окно записи поверх всех окон и мешает ему работать.

## Грабли, проверенные на этом маке

- **Ответвление системного звука (process tap).** Основной способ записать
  собеседника, выход при этом не переключается. Три условия, без любого из них
  тишина без единой ошибки: приватность устройства выключена (иначе его не видит
  ffmpeg), идентификатор ответвления в верхнем регистре (иначе устройство
  создаётся без входных потоков), и в Info.plist есть `NSAudioCaptureUsageDescription`.
- **Разрешение на запись звука системы** выдаётся приложению, а не процессу:
  запуск того же кода из терминала даёт тишину, из бандла — звук. Проверять только
  на собранном приложении. Пересборка меняет подпись, и разрешение нужно выдавать
  заново — предупреждать пользователя при обновлении.
- **Aggregate-устройство** (запасной путь для macOS старее 14.4). Ключ списка
  подустройств именно `subdevices`. С `sub` macOS 27 создаёт устройство без выходных
  потоков: оно есть, звук в него не идёт, и звук собеседника молча не пишется.
  Это одна из причин пустой расшифровки 17.09.2026.
- **Номера входов ffmpeg — не идентификатор.** Они меняются, как только меняется
  набор устройств: подключился микрофон телефона, наушники, появилось наше
  ответвление. 22.09.2026 на этом пропала запись созвона: номер выбрали при
  открытии окна, а к запуску он указывал уже на другое устройство. Устройства
  задаются ИМЕНЕМ (`-i ":MacBook Air Microphone"`), номер — только запасной путь.
- **Звук записи сохраняется** в `audio.flac` рядом с расшифровкой и живёт неделю.
  Без него разбирать жалобы на плохую расшифровку нечем: аудио уже не вернуть.
  Оттуда же работает «Расшифровать заново» — запись уходит одним куском.
- **Ровный ноль на дорожке — это поломка, а не тишина.** Живой микрофон всегда
  даёт хотя бы шум. Захват проверяет первые пять секунд и один раз сам
  перезапускается, заново разрешая имена устройств.
- **Свои устройства нельзя предлагать как микрофон.** Ответвление выглядит как
  обычный вход, и выбор «лучшего микрофона» однажды записал приложение само в себя.
- **Дорожки, а не смесь.** Микрофон идёт левым каналом, собеседник правым, склейка
  через `join`, а не `amix`. Расшифровка получает `multichannel` и больше не гадает,
  кто говорит: раньше метки спикеров у каждого куска записи были свои, и один
  человек превращался в нескольких.
- **Кодировка в собранном приложении.** Под py2app локаль US-ASCII, поэтому
  `subprocess.run(text=True)` падает на кириллице в именах устройств. Всегда bytes
  и `.decode("utf-8", errors="replace")`.
- **Показ окон.** Приложение живёт в строке меню, окна показываются только в обычном
  режиме. Возврат в фоновый режим сразу после показа прячет только что открытое окно:
  окно создаётся, ошибок нет, а на экране пусто. Режим возвращается в
  `windowWillClose_`, когда закрылась последняя панель.
- **Модальные окна.** Пока открыто модальное окно, меню в строке состояния не отвечает.
  Все окна кроме настроек немодальные, на колбэках.
- **PyObjC.** В классах-наследниках `NSObject` только методы по соглашениям Objective-C,
  вида `name_(self, sender)`. Логика выносится в обычные функции.
- **Иконка.** Внутри бандла должна лежать настоящим файлом. Симлинк на файл в Рабочем
  столе или Документах система не прочитает, будет битый значок.
- **Логи библиотек.** `urllib3` на уровне DEBUG пишет в лог токен бота. Сторонние
  логгеры приглушены до WARNING, так и оставить.
- **Звуковой сервис.** Иногда виснет целиком: ffmpeg не отдаёт звук, `say` не отвечает.
  Лечится `sudo killall coreaudiod`, пароль вводит Саша.
- **audioop** удалён в Python 3.13, громкость считается через `array`.
- В zsh `log` — встроенная команда, для системного журнала писать `/usr/bin/log show`.

## Секреты

Ключи лежат в `~/Library/Application Support/Live Transcriber/config.json`,
права только для владельца. В репозиторий не попадают: конфиг вне проекта,
`config.example.json` пустой. Перед коммитом проверять, что в коде нет ни ключей,
ни настоящего идентификатора чата — реальный id один раз утёк в пример в докстринге.

## Проверка перед релизом

- Запуск из исходников, окно записи появляется
- «Проверить звук»: микрофон слышит, звук собеседника доходит
- Короткая запись целиком: расшифровка, итог, окно итога, сообщение в Telegram
- Меню после остановки: значок белый, пункты активны
- История открывается, записи на месте
